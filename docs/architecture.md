# Как устроен RigForge

## Разделы

Три раздела переключаются по hash в адресе: `#build`, `#catalog`, `#saved`. Кнопки «назад» и «вперёд» в браузере работают. Окно с подробностями о детали — `<dialog>` поверх текущего раздела.

## Состояние

Всё состояние хранится в одном объекте в `src/main.js`:

- `build` — текущая сборка: название, бюджет и по одной детали на каждую из 9 категорий;
- `saved` — сохранённые сборки;
- `catalog` — категория, поиск, фильтры, сортировка, статус загрузки и найденные товары;
- `money` — выбранная валюта и курсы;
- `reviews` — отзывы по id товара.

Модули из `features/` только рисуют это состояние и вызывают функции, которые им передаёт `main.js` (`onAdd`, `onRemove`, `onSave` и т. д.). Своей копии сборки у них нет.

## Данные

Товар после загрузки приводится к одному виду (`core/products.js`):

```
{ id, category, manufacturer, name, model, priceMinor, currency, offers, specs, imageUrl, popularity, ... }
```

- Цены хранятся в пенсах целым числом (`priceMinor`), чтобы не было ошибок округления. Неизвестная цена — `null`, а не 0.
- Курсы валют применяются только при выводе (`utils/format.js`), сами данные всегда в фунтах.
- В сборку попадает короткая копия товара (snapshot), поэтому сохранённые сборки открываются без запросов к API.

## Запросы и ошибки

`api/vantaspec.js`:

- каждый запрос проверяет `response.ok` до чтения JSON; ответы 404, 429, 500, сетевая ошибка, таймаут и не-JSON дают понятное сообщение;
- старый запрос отменяется через `AbortController`, если пользователь сменил категорию или поиск;
- загруженная категория кешируется в памяти;
- если модель пропала из VantaSpec, остальные модели категории всё равно загружаются.

В каталоге четыре состояния: «Загрузка…», товары, «Ничего не найдено» и ошибка с кнопкой «Повторить».

## Хранение

`core/storage.js` хранит сборки, отзывы и валюту под одним ключом `rigforge:state:v1` и проверяет данные при чтении. Если `localStorage` недоступен, сайт работает, но предупреждает, что после закрытия вкладки данные не сохранятся.
